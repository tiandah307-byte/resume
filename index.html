01 / About

数据比模型更稀缺，也更需要工程化

在一次肺部 CT 影像标注项目里，同一张片子、同一份标准，不同标注员却给出了完全不同的结论。那一刻我意识到：医疗 AI 的瓶颈往往不在模型，而在数据与验证它的人。

于是我先做数据质量工程：用 LabelStudio + 矢量化校验 + 三级审核把标注一致性从 82% 提到 94%，把清洗耗时从 8 秒压到 0.3 秒。在皮肤病变识别项目里，我用 Grad-CAM 让模型"说出理由"——因为医生不会采信一个黑盒。

实习把我推向了另一端：在医疗 AI 公司，我既写医生工作站与运营站的前端，也独立开发癫痫专病的 RAG 后端。我亲眼看到 AI 能力与"医生真正愿意用"之间的距离——它由数据规则、审核闭环与交互设计决定。

为了在这个密度下持续交付，我把 AI Coding 做成了流程：用规则文件约束 Agent、用方案与接口契约提供上下文、用单测与浏览器自动化截图做验收回路。

把"疾病知识库 + 患者病历 + 大模型"接成一条可用于辅助诊疗的链路：这是我在实习中独立开发的后端服务，也是医院癫痫专病场景的 AI 能力底座。

背景 / 问题

  • 疾病定义散落在知识库文档中，医生难以快速对照；患者病历结构不统一，直接丢给大模型容易答非所问。
  • 癫痫场景需要给出"为什么是这个诊断"的依据，纯生成式回答无法满足临床审阅要求。

做法

  • 病历规则化选取：同一 member_id 下优先选 label_data 中可提取时间最新的记录，全部无法提取时才回退 created_time / id，避免"补录病历"覆盖真实病程。
  • RAG 链路：病历摘要 → embedding → Milvus 检索 top-k 疾病定义 → vLLM（Qwen3.5-9B）输出 Top5 候选疾病 + 概率 + 理由。
  • 知识与查询：病因 / 诱因查询返回全部"机制组合"并去重与空结果兜底；SNOMED-CT 癫痫知识库（Excel → 209 条 JSONL）入库 Milvus。
  • 相似患者：动态读取 level3 / level4 标签结构构建画像与向量库，同 tag_code 取最新、无有效标签跳过并统计 skipped，输出可解释的 Top 标签贡献（parent / child 结构）。
  • 工程化：dev / uat / prod 三环境 collection 与产物隔离、成员级数据隔离、统一日志工具、Docker env_file 部署。

结果

  • 交付 5 类 HTTP 能力；为该项目后端仓库的首批提交作者（20 commits）。
  • 前端"病情洞察"直接复用该推理链路。

把运营站从"一页一写"改造成"配置驱动"：新模块从写组件变成填配置。

背景 / 问题

  • 用户数据台 / 用户服务台 / 积分商城的页面结构高度相似（Tab + 指标卡 + 表格 + 图表 + 下钻详情），差异只在字段与数据。
  • 原实现每页重写组件，新增模块成本高、口径容易不一致。

做法

  • 通用渲染：ModuleView 读取 ModuleOverview（tabs / stats / table schema）渲染 Tab、指标卡、表格与图表区块。
  • 能力拆分：BlockRenderer（区块）、ModuleTable（表格 + 行内操作 + 行点击下钻）、SimpleChart（自绘图表，避免为单页引入重型图表库）、DetailDialog（通用详情弹窗）。
  • 统一下钻：指标卡 / 表格行 / 操作按钮统一走 detailKey + params，接口为 /api/operation/{module}/overview 与 /details/{detailKey}，视图层不感知具体接口。
  • Mock 优先：每模块一个 USE_MOCK 开关与同构 mock 数据（overview / details 分离），后端未就绪即可走查全部交互，联调时一键切换。
  • 类型与关系：TS strict 下定义 ModuleOverview / ModuleTab / ModuleStat / DetailView；模块间关系单独建模管理。

结果

  • 基于框架交付用户数据台、用户服务台、积分商城三个业务模块，并接入路由与侧边导航。
  • 新增模块的开发方式从"写组件"转为"填配置 + 接数据"。

一条从脑电信号到解码模型的完整链路：先做信号处理与频段分析，再复现竞赛级的想象语音分类任务。

背景 / 问题

  • 脑电信号幅度小、噪声多，不同任务（静息 / 算数 / 咬牙）下的频段能量分布差异明显，需要先建立可靠的处理与观察方法。
  • 想象语音解码是 BCI 的前沿方向：数据量小、信噪比低、个体差异大（该竞赛公开成绩：随机 20%，最好 82.6%，第二名 75.5%）。

做法

  • 信号处理：对静息状态 / 算数任务 / 咬牙任务三种条件，对比原始波形与预处理（去噪 / 参考处理）后的波形，并绘制 0–45 Hz 功率谱密度曲线（对数坐标）。
  • 频段分析：按 Delta / Theta / Alpha / Beta / Gamma 五频段统计相对功率，对比三种任务下的能量分布差异（咬牙任务 Delta 占比明显下降，Alpha / Beta / Gamma 占比上升）。
  • 分类复现：CAR → 0–1500ms 时间窗 → 2 倍降采样 → 12,352 维时域特征 → StandardScaler + PCA(60) → QDA（reg_param=0.7）；对照实验为频带功率 / FBCSP / Riemannian（20–45%）＜ ExtraTrees（约 57%）＜ PCA+ExtraTrees（68.4%）。
  • 防泄漏：标准化与 PCA 只在训练集（最终为训练 + 验证）拟合，测试集只做 transform；超参全部由验证集选择，测试标签仅用于最后一次评估。

结果
